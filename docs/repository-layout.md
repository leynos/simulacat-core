# Repository layout

The repository contains the TypeScript package, its tests and fixtures, the
bundled GitHub schemas, and the tooling used to build and validate the package.
The [architecture](architecture.md) describes runtime boundaries; the
[developers guide](developers-guide.md) covers contributor workflows.

## Tracked project areas

- `src/` contains the TypeScript package. `src/__generated__/` contains
  generated GraphQL resolver types and is regenerated by the `generate` package
  script.
- `tests/` contains Bun tests, feature step definitions, snapshots, and test
  support. `features/` holds Gherkin scenarios loaded by the tests.
- `repository-mock-data/` contains JSON fixture data used by the simulator.
- `schema/` contains the bundled REST and GraphQL schemas; see its
  [README](../schema/README.md).
- `tools/` contains the local Oxlint plugin.
- `example/` contains the TypeScript example server.
- `bin/` contains the package's Node CLI entry point.
- `scripts/` contains package scripts, including the audit runner.
- `security/` contains audit exception data.
- `.github/` contains repository automation configuration and workflows.
- `docs/` contains the project documentation and
  [ExecPlans](execplans/).

## Generated and installed files

`dist/` is the package build output, and `node_modules/` contains installed
JavaScript dependencies. `src/__generated__/` is also generated; run
`bun run generate` to refresh its GraphQL resolver types. These are build or
dependency artefacts rather than hand-maintained source files.

## Root files

`README.md` is the package overview and quick start. `package.json` defines the
package entry points and scripts. `Makefile` provides the repository's
formatting, type-checking, documentation, lint, test, build, and spelling
targets. TypeScript build and documentation settings are held in
`tsconfig.json`, `tsdown.config.ts`, and `typedoc.json`.
